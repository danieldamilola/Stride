Critical

Virtual hosts expose user folders to every website
CriticalSecurityWebViewFactory.cs:128

temp.stride maps the entire user temp directory and user.assets maps the Backgrounds folder to any web origin with HostResourceAccessKind.Allow. Any page can fetch http://temp.stride/<guessed-name> and read files from %TEMP%.

Fix: use Deny or DenyCors and scope mappings to the internal pages that need them.

file:// origin isolation disabled
CriticalSecurityWebViewFactory.cs:92

--allow-file-access-from-files lets a downloaded or opened local HTML file read arbitrary local files via XHR. Stride advertises being the default HTML viewer, so web-downloaded files hit this path.

Fix: serve local files through a scoped virtual host, or gate the flag behind an explicit setting with a warning.

Session IPC token can leak to external sites
CriticalSecurityOnboardingMessageHandler.cs:34, DownloadMessageHandler.cs:146, TabEngine.cs:475

Handlers check the active tab URL, then post the per-session IPC token to the active WebView. Between the check and the post the tab can navigate to a normal website, which receives the token and can forge trusted internal-page messages.

Fix: re-verify core.Source starts with the internal origin immediately before every PostWebMessageAsString, and verify the tab still owns that core.

DownloadStore races itself and corrupts downloads.json
CriticalData lossDownloadStore.cs:44

Item_PropertyChanged fires from download threads and Save() enumerates Items while Add/Remove/ClearAll can mutate the same collection. WPF also throws on cross-thread collection changes bound to the UI.

Fix: guard mutations with a lock, serialize a snapshot inside it, marshal collection changes to the UI dispatcher.

Updates are installed with no integrity check
CriticalSecurityUpdateService.cs:78

The downloaded zip goes straight to Stride.Updater.exe which replaces application files. No hash or signature is verified before launch. The ed25519 signer already exists for the appcast; the package itself is unchecked. Also missing: a re-entrancy guard on DownloadUpdateAsync, a threading contract for progress events, and an await of Shutdown() before starting the updater.

Fix: publish a SHA-256 or ed25519 signature per release, verify before launching the updater, add a semaphore.

MainWindow leaks on every resolution
CriticalMemory leakComposition.cs:126, MainWindow.xaml.cs:75

MainWindow is registered AddTransient but subscribes to singleton events (engine, router, theme manager, single-instance manager) and never unsubscribes. Each resolution keeps the previous window alive forever.

Fix: register MainWindow as a singleton, or detach every subscription in OnClosing.

Leaked WebView when script injection fails
CriticalResource leakTabEngine.cs:592

The try/catch protecting WebView creation ends before InjectAsync. If injection throws, the control is already in the visual tree, unregistered, and never disposed: an invisible live WebView stays in the app forever.

Fix: move all post-creation awaits inside the failure-cleanup block.

Global exception handler swallows every crash
CriticalReliabilityApp.xaml.cs:106

The dispatcher handler sets e.Handled = true unconditionally. Execution continues after any unhandled exception with potentially corrupt state.

Fix: mark handled only for known-recoverable types, or count failures and shut down after repeated ones.

Medium

Theme and link-preview messages bypass the IPC token check
MediumSecurityWebViewIpcBridge.cs:126-175

THEME_COLOR: and LINK_PREVIEW_PEEK: are handled before the token verification, so any web page can spoof the tab theme color or spam link-preview requests for arbitrary URLs.

Fix: move both branches below the trusted-source and token gate.

Live IPC token script injected into every page
MediumSecurityContentScriptInjector.cs:38

wallhaven-token.js with the embedded __IPC_TOKEN__ is registered on document creation for all sites, not just wallhaven. Gate injection on the trusted hosts.

AdBlockFilter: thread-unsafe set, no retry, inconsistent toggle
MediumStabilityAdBlockFilter.cs:17

Static HashSet written on a background thread and read from WebResourceRequested on the UI thread. A failed download sets _isInitialized so there is no retry for the process lifetime. Toggling adblock mid-session only affects new WebViews.

Fix: publish an immutable set via Interlocked.Exchange, retry failures, apply to existing WebViews on toggle.

Dialog suppression heuristic drops legitimate dialogs
MediumBehaviorTabDialogHandler.cs:39

Any script dialog whose text contains "update", "allow", or "human" is silently dropped, gated on AdBlockEnabled which is unrelated. Suppressed beforeunload prompts can strand page JS.

Fix: remove the keyword list; keep the custom dialog for everything.

History rewrites the entire file on every navigation
MediumPerformanceHistoryStore.cs:30

Every Add re-serializes up to 10,000 entries and rewrites history.json. Roughly a 2 MB write per page load at cap.

Fix: debounce saves (30s plus shutdown), append JSONL, or move to SQLite.

AtomicFileWriter: shared temp path, no durability
MediumData lossAtomicFileWriter.cs:12

Concurrent writers to the same target share one .tmp path and can interleave before File.Move promotes a corrupt file. No fsync before the move either.

Fix: unique temp name per write, flush before move, delete the temp on failure.

post_update.flag written to the install directory
MediumBugStartupCoordinator.cs:45

Under Program Files the flag write fails for non-admins, so release notes after an update either never show or show on every launch because the delete also fails.

Fix: move the flag to the AppPaths data directory in LocalAppData, both writer and reader.

Reader sanitizer regex is structurally fragile
MediumSecurity depthReaderSanitizer.cs:24

Tag matching stops at the first >, so unterminated tags and quoted attributes containing > slip through. The script-src 'none' CSP is the real net; the sanitizer header overpromises.

Fix: parse with a real HTML parser, or document that the CSP carries the guarantee.

Reader navigation race in MainWindow
MediumRaceMainWindow.xaml.cs:404

UpdateReaderOverlay disables script, navigates, re-enables at Background priority and clears the programmatic-navigation flag. A user navigation landing in that window gets script disabled and misclassified. Errors are surfaced through the window Title.

Fix: move reader navigation into ReaderService behind one entry point that owns the flag.

Async void extension initialization
MediumStabilityWebViewFactory.cs:152

Dispatcher.InvokeAsync(async () => ...) binds the Action overload. Exceptions escape unobserved and a failure can permanently block extension retries because the guard flag never resets.

Fix: use the Func<Task> overload with .Task.Unwrap() and await it inside the try.

Shutdown disposes the activation gate mid-use
MediumRaceTabEngine.cs:1343

Shutdown disposes _activationGate while an in-flight ActivateAsync may be between WaitAsync and Release, throwing ObjectDisposedException.

Fix: track in-flight activations, or await the gate before disposing.

PreviewKeyDown is async void with late Handled
MediumInputMainWindow.xaml.cs:1295

e.Handled = true runs only after the awaited shortcut action. Key repeat queues multiple tab switches during the await.

Fix: set Handled synchronously when the combo matches, dispatch the action without awaiting, guard with an in-flight flag.

Settings values injected into HTML unescaped
MediumSecuritySettingsPage.cs:162

Custom shortcut names from the user-editable settings file go into the internal settings page without escaping. JsEncoder exists for exactly this and is barely used.

Single-instance pipe accepts anything from any local process
MediumSecuritySingleInstanceManager.cs:58

No ACL on the named pipe and no payload validation beyond JSON shape, so any process can inject URLs that open as tabs. One slow client also blocks the accept loop, dropping arguments from later instances.

Fix: add a current-user PipeSecurity, bounded reads with a timeout, two server instances.

Download pause and resume may be cosmetic
MediumBugCustomDownloadManager.cs:30

Pause/Resume/Cancel only flip DownloadItem.State. Unless the handler calls CoreWebView2DownloadOperation.Pause()/Resume(), the UI shows Paused while bytes keep flowing. Two parallel sources of truth for download state can drift.

Dynamic WebView typing everywhere
MediumTech debtTabEngine.cs:37

TabEngine holds WebViews as dynamic. Every typo becomes a runtime exception and hot loops like ShowOnlyActiveWebView pay binder calls. LinkPreviewWindow.xaml.cs:14 does the same.

Fix: define a small adapter interface over the two WebView2 control types.

Dead UI controllers drifted from MainWindow copies
MediumArchitectureServices/UI/*, MainWindow.xaml.cs (1,617 lines)

CommandBarController, TabStripController, WindowLifecycleController, TCLensLauncher, ToolbarTintAdapter, SecurityBadgeHelper, LoadingAnimationController, WindowChromeHelper are never instantiated. MainWindow re-implements all of them and the copies already differ: URL label formats and duplicate-tab behavior disagree. This violates the AGENTS.md rule that MainWindow stays clean.

Fix: migrate MainWindow logic into the controllers one at a time, or delete them. Pick one direction.

Favicon caches grow without bounds
MediumDisk usageFaviconLoader.cs:28

The disk cache under favicons/ is never pruned. Failed loads cache null in memory until restart.

Two settings snapshots at startup
MediumBugApp.xaml.cs:43, Composition.cs:24

Both call settingsStore.Load(), creating two independent mutable copies of settings that can disagree. Also HttpClient is registered twice while BrowserViewModel ignores DI and uses its own static.

Things to add

Feature gaps worth filling
  • Update package verification: publish SHA-256 or an ed25519 signature beside each release zip and verify it before the updater runs. The signing tooling already exists.
  • Settings export and import: a one-click full JSON backup of BrowserSettings, shortcuts, and blocklists. All stores already round-trip JSON, so this is mostly plumbing.
  • Per-site settings: remember zoom, JavaScript toggle, and user-agent override per domain, stored next to history.
  • SQLite storage backend: for history and downloads once they outgrow JSON. Removes the rewrite-per-navigation cost and the Save race in one move.
  • stride://health page: shows extension status, adblock filter age, hibernation counts, cache sizes, update state. Turns invisible internals into a debuggable surface.
  • Tab search overlay: search open tabs by title and URL from the command bar. The tab strip is the only finder today.
  • Audio per tab: mute toggle and audio indicator on tab pills. Hibernation already detects playing tabs, so the signal exists.
  • Bookmark import depth: recursive folder import with folder mapping.
  • Test coverage for stores and handlers: DownloadStore concurrency, HistoryStore eviction, and the message handlers have no tests today.

Things to change

Structural changes
  • Finish or kill the R5 controller migration. Eight dead controllers plus a 1,617-line MainWindow is the worst state to be in: two sources of truth that already disagree. Migrate one controller per round, exercise the app after each.
  • Replace dynamic WebView references with a small adapter interface shared by the standard and composition controls.
  • One HttpClient, one settings instance. Register HttpClient once and inject it into BrowserViewModel; load settings once in Composition and pass the instance everywhere.
  • Unify download state: one owner for active download operations, one for persisted items, with an explicit bridge.
  • Move reader navigation behind ReaderService with a single entry point that owns the programmatic-navigation flag.
  • Move TCLens payload out of static fields into the already-written TCLensLauncher service.
  • Register MainWindow as singleton or unsubscribe all events on close; same for LinkPreviewWindowController.Attach re-subscribing engine events.
  • Generate ReleaseNotesProvider from ReleaseNotes.md at build time so the in-app notes never drift.
  • Gate theme-color and link-preview IPC below the token check and gate wallhaven scripts by host at injection time.

Things to reduce for lightweightness

Trim fat without losing features
  • Drop AdBlockFilter entirely or fold it into a setting default off. uBlock Origin is the real blocker per the code's own comment. Removing the filter list download, the static set, and the WebResourceRequested hook simplifies startup and every request.
  • Delete the eight dead UI controllers if migration is not happening. Less code, less drift, faster builds.
  • Compile out StressTestRunner from release builds with a conditional compilation symbol. It is a dev tool shipping to users.
  • Prune the favicon disk cache with a size cap and LRU eviction; also stop caching failed loads.
  • Debounce or cap history: besides the perf win, cap stored entries lower than 10,000 by default and make it a setting.
  • Lazy-inject scripts: wallhaven, reader, and link-preview scripts are registered for every document; only wallhaven needs gating, but the others could skip internal pages.
  • Clean the repository root: dump.cs, fix_*.ps1 scratch scripts, and stale analysis JSON reports (core_report.json, unified_report.json, multilang_report.json) do not belong in the repo. The publish/ directory duplicates resources.
  • Session restore size: persisting every open tab on close is fine, but skip hibernated thumbnails for background tabs beyond a count.
  • Trim browser arguments: audit BuildBrowserArguments; every undocumented flag is a support surface.

Things to modify for lightness and customization

Make behavior configurable instead of hardcoded
  • Settings-driven browser arguments: expose hardware acceleration, process-per-site, and file access flags in an advanced settings section with safe defaults.
  • Virtual host access level as a constant worth a setting: internal hosts should be DenyCors for pages and Allow only for internal origins.
  • Per-feature script toggles: adnuke currently rides on AdBlockEnabled. Give the YouTube ad nuker its own switch like the enhancer and unhook have.
  • History retention setting: days or entry count, with a clear-now button on a stride://history page if one does not exist.
  • Favicon cache size setting and a clear-cache action.
  • Toolbar density: compact and comfortable modes via a single Height resource, since the toolbar height is already one binding point.
  • Shortcut conflicts surfaced in settings: KeyboardShortcutMap supports rebinding; detect and highlight duplicates instead of silently winning by order.
  • Fullscreen monitor choice: fullscreen currently targets the nearest monitor; a setting for "monitor with cursor" vs "window's monitor" is one line in FullscreenController.
  • Session restore scope: setting for all tabs, pinned only, or none, instead of the single RestoreSessionOnStartup toggle.

Done well

Worth keeping exactly as they are
  • GoodPer-session IPC token design. Internal pages on about:blank authenticate with a per-instance token instead of fragile origin checks. Right call for NavigateToString pages.
  • GoodExtension TOFU hashing. Extensions ship with the app and are hash-verified on load, never downloaded after install.
  • GoodHibernation guards. Tabs playing audio or mid-download are refused eviction; the preview generation counter handles races cleanly.
  • GoodReader mode defense in depth. Allow-list sanitizer, javascript/data/file URL rejection with base-URI resolution, and script-src 'none' CSP.
  • GoodCOM exception discipline. ContextMenuRequested guards every Has* property before string reads.
  • GoodAtomicFileWriter used consistently for every JSON store, with fail-soft loads that never crash startup on corrupt state.
  • GoodKeyboardShortcutMap. Declarative table with runtime rebinding driven by settings, replacing a 175-line key cascade, with test coverage.
  • GoodFullscreen state machine. Pure, unit-tested, idempotent transitions shared by F11 and WebView2 events, with native monitor bounds in the chrome manager.
  • GoodYouTube tools config pipeline. JSON-serialized configs persisted in localStorage, identity-tracked listeners, live reload without observer stacking after the recent fixes.
  • GoodTest suite discipline. 222 passing tests over the pure logic: navigation policy, focus matcher, shortcuts, reader, link preview, context menus, fullscreen.
