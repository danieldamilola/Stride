Security findings

TCLens extension pulled from a mutable branch with no verification
CriticalSupply chainExtensionManager.cs:24

uBlock is pinned to a release tag and TOFU-verified with SHA-256. TCLens downloads T-C/archive/refs/heads/main.zip, an untagged branch that changes on every push, with no hash check at all. A compromised repo means arbitrary code runs as a browser extension on every install.

Fix: pin a release tag, ship a SHA-256 with the app or appcast, and verify on every download like uBlock.

temp.stride virtual host reads the user temp directory
CriticalPrivacyWebViewFactory.cs:128

Any web page can fetch files from %TEMP% through http://temp.stride/. Temp folders hold browser dumps, document drafts, and installer payloads. Both a security and a privacy hole.

Fix: map only the specific subfolder needed with DenyCors, and serve internal pages from it.

Update package integrity unchecked
CriticalSupply chainUpdateService.cs

The micro-updater replaces application files with a downloaded zip after no signature or hash verification. The ed25519 signer and appcast already exist; wire verification in before the updater launch.

file:// sandbox disabled
CriticalSandbox escapeWebViewFactory.cs:92

--allow-file-access-from-files lets one local file read other local files. A malicious HTML attachment opened in Stride can exfiltrate documents from disk.

Fix: serve local files over a scoped virtual host with a null origin, or make the flag an explicit warned setting.

IPC token handed to whatever tab is active
MediumIPCOnboardingMessageHandler, DownloadMessageHandler, TabEngine.cs:475

URL-check-then-post races let a normal website receive the session token and forge internal-page messages. Re-verify core.Source immediately before each post.

Theme and link-preview messages skip authentication
MediumIPCWebViewIpcBridge.cs:126

THEME_COLOR: and LINK_PREVIEW_PEEK: perform token validation, but the token itself is exposed to injected scripts. The actual risk is token exposure to the page environment, requiring scoped token-bearing scripts or an equivalent renderer trust-boundary check.

Session token script registered on every page
MediumIPCContentScriptInjector.cs:38

wallhaven-token.js carries the live IPC token and is registered for all documents. Register it only for the trusted wallhaven hosts.

Named pipe accepts commands from any local process
MediumLocal attackSingleInstanceManager.cs:58

No ACL and no validation: any local process can open arbitrary URLs in tabs, which combined with the file:// finding becomes local file exfiltration. Restrict the pipe to the current user and validate payload length and scheme.

Settings file content reaches internal page HTML
MediumInjectionSettingsPage.cs:162

Custom shortcut names are interpolated without escaping. A malicious or tampered settings file injects script into a trusted internal page. Escape with JsEncoder.

Downloads: no size cap, no filename sanitization
MediumRobustnessTabEngine.cs:836

SaveImage streams unbounded bytes to disk; download filenames come from URLs without stripping path separators or reserved names. Cap size, sanitize names, resolve inside the target directory.

Script dialog keyword suppression
MediumBehaviorTabDialogHandler.cs:39

Dialogs mentioning "update", "allow", or "human" are silently dropped. This trains users that security prompts disappear, and it is gated on AdBlockEnabled which is unrelated.

Blocklist cache named with MD5 (Fixed)
FixedCrypto hygieneFocusBlocklistService.cs:190

MD5 was only used for cache file naming, not verification. Switched to SHA-256 for hygiene.

Process-per-site merges same-site processes (Fixed)
FixedIsolationWebViewFactory.cs:91

Reduces isolation between distinct sites sharing a registrar domain. The inaccurate comment claiming Site Isolation was restored has been fixed to document this tradeoff.

Security posture done right
  • GoodChromium-level telemetry hardening: --disable-background-networking --disable-breakpad --disable-component-update --disable-sync --metrics-recording-only --disable-domain-reliability. Most Chromium forks never bother.
  • GoodSmartScreen on by default with the reputation check aligned to the same setting (IsReputationCheckingRequired), so the toggle is honest.
  • GooduBlock Origin: pinned release tag, SHA-256 TOFU verification, never downloaded again after install.
  • GoodReader mode: allow-list sanitizer, javascript/data/file URL rejection, script-src 'none' CSP.
  • GoodLink preview window denies all permissions, cancels downloads, blocks new windows.
  • GoodPer-session IPC token replaces fragile origin checks for about:blank internal pages.

Privacy findings

Address-bar text is sent to DuckDuckGo
LowPrivacySuggestionProvider.cs

Suggestion cycles post the current query text to duckduckgo.com/ac/. This is controlled by a user setting and debounced locally to prevent excessive requests.

Favicon fallback proxy uses DuckDuckGo
LowPrivacyFaviconLoader.cs

Favicons resolve through WebView2's native API first and are cached aggressively. If a favicon is missing, the app falls back to icons.duckduckgo.com/ip3/<domain> only if the user has enabled the proxy in settings.

No private browsing mode
MediumGap

No incognito window and no per-tab do-not-record mode. History, session, and favicons capture everything. For a browser with a Focus Mode identity, a throwaway session using a separate WebView2 environment and no history writes is a natural companion feature.

"Clear data on exit" clears less than users expect
MediumGapBrowserSettings.cs:54

The setting is off by default and, when enabled, clears only the WebView2 profile. It never touches history.json, session.json, the favicon cache, or the log files, which are the most identifying artifacts Stride owns.

Fix: expand the option to the JSON stores and logs, or split into per-category checkboxes.

Trace log never rotates and can hold URLs (Fixed)
FixedPrivacyApp.xaml.cs:29

A file trace listener captures all Trace.WriteLine output into stride.log. Exception messages in navigation and download paths can embed full URLs. The log is now capped at 1MB and deleted with clear-on-exit.

History and session stored as plaintext JSON
LowPrivacy

Any process, any person at the keyboard, or any disk image reads the full browsing record. This matches what Chrome does, so it is not unusual. DPAPI-protecting history and session files would be a privacy differentiator worth considering for a browser positioned on privacy.

Privacy posture is undocumented to the user
LowTransparency

Stride makes genuinely rare choices: no telemetry, Chromium phoning disabled, BYOK AI. None of this is written anywhere a user can find it. A short stride://privacy page listing every network destination and on-disk artifact, matching the tables above, would make the work pay off.

Privacy posture done right
  • GoodNo telemetry, analytics, crash reporting, or tracking anywhere in the codebase. The egress list above is complete.
  • GoodChromium background networking, sync, metrics, and component updates disabled at the flag level.
  • GoodTCLens AI is bring-your-own-key and user-triggered; nothing is analyzed or transmitted automatically.
  • GoodSmartScreen defaults to on: privacy-respecting defaults with real phishing protection.
  • GoodDuckDuckGo chosen over Google for search suggestions and favicon proxying, the least-bad third parties available.
  • GoodFocus mode blocklists are cached locally with content hashing, so repeated focus sessions do not re-fetch.

Priority order

If you fix five things
  • 1. Verify the update package before the updater runs. It is the highest-value target in the app.
  • 2. Close temp.stride and drop or gate --allow-file-access-from-files.
  • 3. Pin and hash the TCLens extension download.
  • 4. Make clear-on-exit actually clear everything, and write the stride://privacy page.
