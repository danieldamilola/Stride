Top recommendation

4. Make the web message contract enforce itself, then 5. Give the stores a file-system seam

The contract fix is first because it is the cheapest Deepening that buys the most safety. One parity test that scans every .html resource for __T + '<prefix>' and asserts a registered MessageRoute covers it catches six existing drifts, closes a live single-quoted JSON.parse injection in a page that holds the IPC token, and makes every future message addition fail the build instead of failing silently with a Trace line. No interface changes, no migration, one new test file.

Right after it, the stores seam. Constructor-injecting the file-system target turns five untestable modules into five tested ones with the same interface surface. That is the highest leverage-per-line change in the review: one seam, five modules, every persistence path gains coverage, and the PascalCase versus camelCase divergence becomes a pinned expectation instead of a latent migration bug. Together they are a single PR shape: enforce the outer boundary, then make the persistence boundary substitutable.

If you want the highest-risk correctness fix first instead, swap in 1 and 2 as the next sweep. Reader-blind hibernation writing about:blank over tab.Url and the non-deterministic 4000 ms timeout race are real data-loss bugs, they just need more surgery than the two wins above.
