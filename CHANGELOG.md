# Unreleased

- Context menu separators now use the theme's line colour instead of the WPF default, so they stay visible in both themes.

* Added optional history retention and clearing on exit to the roadmap.

* The dark theme uses neutral charcoal backgrounds, gray borders and neutral text across the browser frame, address suggestions, link previews and built-in pages.

* Dark internal pages use the native theme colors for backgrounds, cards, hover states and borders, replacing the brown tones.

* Removed the initial "Changes save automatically" text from Settings.

* Switching tabs hides the previous page immediately. Late activations and background WebView initialization cannot replace the selected page or cancel its activation, including when opening internal pages.

* Validation tools follow the newer history and telemetry contracts. Extension repair tests reuse one file snapshot, and deadline checks run apart from disk-heavy tests.

* Integrated the newer browser branch into local main while preserving the pending Settings and internal-page fixes. The floating command bar stays removed, tabs compact when space runs out, and address entry has no outer border.

* The default accent is #d4d4d4. Settings validate and save changes before applying them, report save failures and restart requirements, support shortcut recording, and preserve locked Focus rules during reset.

* Internal pages share readable theme colors, keyboard focus, dialog behavior, and narrow layouts. New Tab includes wallpaper previews and address validation. History and New Tab respect the icon proxy preference.

* **YouTube Unhook Works On Pages That Refuse Storage**: On a page where the browser blocks site storage, or in a private window, YouTube Unhook lost every setting at once and hid nothing, with nothing saying why. It now takes its settings from the page itself when the page will not keep them. Pages that do store them are unchanged, and a live settings change still applies without a navigation.
* **A Window Close Fault Isolation**: A fault raised while a window was closing, outside the writes that were already guarded, skipped the rest of the close. The window stayed on screen with its own close already cancelled, so pressing close again did nothing, and the fault reached the WPF dispatcher as an unhandled exception. Every step of a close now runs whatever the step before it did, and the final close is always scheduled, with a scheduling fault traced rather than left to escape. Link preview dismissal and tab recycling are isolated so a fault in either does not skip the other. What is written and cleared is unchanged. Whether a real window then closes is WPF behaviour this build does not exercise.

* **Favicon third party lookups are opt in, and local hosts are refused**: The Favicon Network Fallback switch now defaults to off. Turning it on may send a site's hostname to DuckDuckGo's icon service while Stride loads a page icon. Profiles whose settings file was written before this change are migrated once on first start after the update, and only that setting changes. A saved "on" from those builds came from the old default, not a choice, so it cannot count as consent. The migration is saved so later choices persist. History, autocomplete and new tab shortcut rows use memory and disk icon caches only. The network lookup refuses IP literals, localhost, single label names, reserved suffix trees and their apexes, including `home.arpa`, and names that cannot be reduced to an ordinary ASCII domain. Host comparison ignores case and trailing dots, and internationalized names are reduced to ASCII. Stride makes no DNS lookup for this decision. Engine provided icons are unchanged.
* **Crash uploads are disabled for WebView2, and local dumps are bounded**: Each WebView2 environment uses Microsoft's custom crash reporting option, which prevents Windows from sending crash data to Microsoft's endpoint. Other WebView2 diagnostic data still follows the Windows diagnostic data setting. SmartScreen, security updates, browser arguments and extension support are unchanged. The report folder WebView2 names is pruned at startup. Stride checks that it is within this run's profile and that every path component is not a reparse point before it reads files and before it deletes dumps. A detected link stops cleanup. Cleanup considers only top level `.dmp` files, removes dumps older than seven days, keeps at most five and 100 MiB, and removes the oldest first. A locked or still writing dump is left for the next start and reported. The result does not certify the folder within limits if a selected dump remains or an entry cannot be inspected. All windows sharing the profile join the same pass. The path checks reduce the risk from links already present, but they are not atomic against a process that swaps a directory between the checks and deletion. Other WebView2 diagnostic data and Strict tracking prevention compatibility remain governed by their own settings and site behavior.
* **Tracking Prevention Can Be Set To Strict**: Settings has a Tracking prevention choice next to the other privacy controls. Balanced is the default and is what the browser already used. Strict blocks more trackers and works alongside uBlock Origin, and Microsoft documents that it can make some sites behave unexpectedly, which the setting now says. There is no off switch, because the browser should not offer to remove its own protection. The choice is saved, restored on the next start, reset by Reset Defaults, and applied to every browser profile the app creates, so a profile that once ran Strict returns to Balanced when the setting says Balanced. Changing it reaches open windows and tabs immediately without a restart or a page reload.
* Updated contributor guidance to use `CHANGELOG.md` and removed the obsolete release-management skill requirement.
* Removed generated build clutter, 1150 files and 271.82 MB: two abandoned WPF markup compile temporary projects left at the repository root by an interrupted build, three empty WPF temporary output folders, an empty isolated test output folder, intermediate output from the isolated and artifact builds, and the test project's own build output. Added ignore rules for WPF temporary projects so an interrupted build does not surface them as untracked files again. Test results, hang dumps, binaries that existing reports cite by hash and the recovery verification evidence are untouched, as is the current debug build output, which a live `dotnet run` process still holds open. No product or test source changed.
* **Blank Link Tab Readiness Synchronization**: Link clicks opening new tabs no longer leave blank tabs titled New Tab when WebView2 initialization races tab activation. TabEngine publishes a shared per-tab readiness operation before any asynchronous wait, ensuring repeated activation awaits in-flight creation without spawning duplicate controls or treating dictionary registration as complete readiness. Setup completion takes precedence over control existence. Popup adoption awaits core readiness before assigning the new window, cancellation remains local to the caller without abandoning shared initialization or other waiters, initialization failures and cancellations are settled explicitly, failed sentinel tabs are cleaned up without recording them in the closed tab history, and deferrals complete exactly once.
* **Privileged IPC Separation**: Web message routing separates external web content telemetry from privileged browser commands. Injected scripts on web pages carry a telemetry token, which reaches theme colour and link preview and nothing else. A privileged command has to arrive from an about:blank source, from a tab that currently holds an internal document identity, carry the token the whole process shares, and name a route the owning page is allowed to send. Navigating away drops that identity, so a tab which has gone external has no privileges left. Untrusted origins can no longer trigger internal navigation, settings updates or downloads.
* **Six Internal Page Commands Work Again**: The per page route allowlist above left out six commands the pages really send, so those controls were dead: the Onboarding Done button, the onboarding ready handshake, every preference write during first run, Set Default in Settings, and both What is New buttons. Each one now passes the policy of the page that owns it, and the test reads the shipped page markup, so a control that posts a route its own page may not send fails there rather than in front of a user.
* **History Clearance On Exit**: Closing the browser with Clear Data on Exit enabled now clears Stride's custom history store and deletes the history file in addition to WebView2 profile data.
* **Settings Privacy Controls**: Added explicit toggles in Settings for Search Suggestions and Favicon Network Fallback. Users can disable sending address queries to DuckDuckGo and suppress fallback icon lookups.
* **Parked YouTube Enhancer Controls**: Marked parked YouTube Enhancer settings as unavailable in Settings and disabled their controls. Updated Onboarding highlights to describe active YouTube Unhook distraction-free viewing instead of parked player capabilities.
* **Locked Focus Navigation I/O**: Locked Focus mode main-frame navigation checks now use shared live in-memory settings rather than rereading and deserializing settings from disk on every request and redirect.
* **External Protocol Dialog Ownership**: Custom protocol confirmation dialogs now resolve their owner window from the tab's hosting visual element rather than always defaulting to the application main window.
* **Consistent ASCII Punycode Hostname Display**: Valid internationalized domain names now display as canonical ASCII Punycode across the address bar, full address focus view, script dialogs, permission dialogs, link preview headers, and external protocol prompts. Subdomains, IPv4 literals, and bracketed IPv6 literals remain intact, while paths, query strings, fragments, schemes, and userinfo are preserved without string replacement collisions. Navigation targets, user typing, and untouched reload behavior are unaffected.
* New tabs show a muted "Search the web or type a URL" hint in an empty address field. The hint stays while the empty field has focus and disappears when you type. Settings and Downloads keep their page labels.
* Address suggestions follow the active light or dark theme. Typed text stays readable while suggestions are open, and the dropdown rows update their text and background colors when the theme changes.
* Browser windows now enforce the declared 400 by 480 DIP minimum during edge and corner resizing. Native resize limits use the window's current display scale without changing maximize or restore bounds.
* A window resize now begins on the native WM_ENTERSIZEMOVE message and ends on WM_EXITSIZEMOVE, and every SizeChanged in between asks WPF to lay out immediately instead of waiting for the next pass. Whether that shortens the visible catch-up during a real drag is not measured.

* Restored the integrated custom window frame with no native sizing strip above the toolbar. The page stays inside the resize edges, so the sides, bottom and corners below the toolbar remain usable.
* Added a rounded web content frame under Appearance, enabled by default. Pages keep compact spacing and rounded corners without a painted inner outline. The setting applies to open windows and the frame disappears in fullscreen.
* Moved the webpage 3 DIP closer to the toolbar. Tab cards now match the address field's 28 DIP height, and the address field keeps its background and rounded corners without an outline.
* The toolbar stays in one row as the window narrows, with a 400 DIP minimum window width, a shrinking address field and an overflow menu for optional actions where space allows.
* Tab cards use their new bounds immediately when the tab viewport changes during resizing, instead of animating toward an outdated size.

* Inactive tabs show their titles and use the spare tab strip width, shrinking toward favicon width as the strip fills. Pinned tabs stay compact.
* Settings has a compact About Stride card with the app icon, build version, WebView2 SDK, .NET runtime and credits. Update checks and installation controls remain available.

* **The Registration Gate Can No Longer Be Skipped, And Its Rules Are Testable**: Switching tabs while the extension was being registered used to cancel the wait and then load the page anyway, with the registration unproven and a control left live that had never navigated. The last pass of a run could report a ready state for a preference that had already changed, a retry after a window failed could wait twice as long as it was promised, a stale updater marker or an assets file that would not write could remove and re-add a working registration on every start, and finding the old IDM extension cleared the uBlock reference with it, so a live uBlock was left untouched with blocking off and reinstalled with blocking on. A pass now decides from the file work it did itself, so turning ad blocking off and on again no longer removes and re-adds the extension, and a second profile on the same manager can no longer be decided by the first one's preparation. The gate belongs to the engine rather than to the tab switch that started it, so switching never cancels it and closing the window does, and a cancelled wait drops the control instead of leaving a blank one behind. The newest preference is applied before a run reports completion, and a run that cannot settle on it reports a failure rather than a ready state for an older one. One wait budget covers every retry. A stale marker no longer cycles a healthy registration, files that cannot be prepared keep the working extension and report the failure, and a genuine version or location change still re-registers once. Removing IDM no longer touches uBlock. A navigation that had to wait is dropped when a newer url or a generated page owns the tab, including the startup navigation of a tab that is still being built. Startup no longer prepares extension files on its own, so the coordinator is the only writer for the profile. These decisions are pure functions covered by tests, and a ready answer is tied to the profile the control reported. Filter readiness is still not claimed.

* **uBlock Is Registered Before The First Page Load**: uBlock Origin was installed on a background task that nothing waited for, so the first page request left while the extension was still going in, and every window ran its own installation against the one shared profile. Registration is now awaited before the first external navigation of a tab, including a url typed into a new tab, and one registration is shared by every window on the same profile. The enabled state is read back from the profile instead of being inferred from the extension folder existing, so a missing or disabled extension is reported as a failure rather than as success. Turning ad blocking on or off in Settings now reaches the live extension at once, with no page reload and no reinstall, and resetting settings reconciles it too. The installed filter files are only rewritten when their content really changes, so a warm start leaves the bytes and the modification times of a folder WebView2 has registered untouched, and a profile with blocking off and nothing installed no longer unpacks the extension at all. Internal pages and the popup handoff sentinel are never held back. Filter readiness is not claimed anywhere: WebView2 has no API that reports it, so the state stays unverified until a controlled run sees the shipped filters block a request. Whether first load playback on YouTube improves is not measured here.

* **The Saved List Registry Is Actually Read Back, And A Registered Folder Is Repaired In Place**: Two defects in the filter list repair. The registry storage key moved in the extension's script but the code that reads the saved registry back out of what the storage read returned still looked for the old property name, so every start after the repair missed its own cache and rebuilt the registry from the bundled file, throwing away the update schedule and the remote urls the previous start had saved. All four places move together now, the storage read, the two callback reads and the storage write, and the check that decides a folder is repaired needs all four rather than any of them, so a script that is partly migrated is finished rather than reported as healthy. The extension's own loader is executed over two background lifetimes sharing one cache to prove it: the first rebuilds from the repaired file and saves under the new key, the second reads that save back and keeps the newer remote url and update schedule it carries, and a script with the callback put back fails the same check. Separately, a folder WebView2 was holding was repaired in place, so the browser was reading bytes that changed underneath it, and an earlier revision of this change answered that by removing the extension and adding the same folder back. Removing and re-adding the same path is a reinstall, and a reinstall discards everything the extension had stored for itself: measured on a real profile, a durable storage key and a non-default list selection were both gone after a remove and add. The two files the repair touches are now written over the registered folder in place, with no removal and no re-add, which kept the registration, kept that storage key and kept the selection through a new process as well. A write that fails part way puts every file back, so the folder never ends up half repaired. A genuine version or location change still re-registers once. A folder whose state cannot be read is reported as needing work rather than as healthy, and a healthy folder is still written nothing and re-registered nothing, including when ad blocking is turned off and on again. This is not a claim that first load playback on YouTube improves; that is not measured here.

* **Filter Lists Can Update Again**: The preparation step used to delete the remote filter urls from the extension's assets file, and uBlock Origin then refused to update any of its lists, because its own updater skips a list whose entry has no remote url and the installed lists were 66 to 73 days past the expiry they declare. The urls are kept now, the mirror and diff keys stay as the package ships them, and the bundled copies in the folder stay first in the read order so a first run still works with no network. The mirror and diff keys keep their leading caret, which means the updater does not read them and updates each list from the origin url instead. That is the extension's normal operation and it does not stop diff requests, because the extension's own diff updater derives the cdn hosts from those origin urls; what the caret removes is the mirror and diff hosts the package happened to name. A folder an older build already stripped is repaired in place, once, with the two rewritten files taken from the pinned package. Nothing is removed and nothing is added back, so your selected lists, custom lists, rules and settings are not touched: that is measured, not assumed, because the same repair used to remove the extension and add the folder back, and a reinstall discards everything the extension stored for itself. The repair does not run again once the folder is right. Whether this changes first load playback on YouTube is not measured here.

* **YouTube Is Left To The Extensions And Unhook**: The browser no longer keeps its own ad blocklist. A host request filter ran on every request in every context and answered a fixed set of YouTube ad endpoints and ad image hosts with an empty 200, in parallel with uBlock Origin, so a real response could be emptied before the extension or the page saw it. That filter, the domain list it downloaded at startup, and its two call sites are gone. Ad blocking is now owned by the uBlock Origin extension alone, which the ad blocking switch still enables and disables. The built in YouTube Unhook script is unchanged and is still injected on a document start, still follows its own preferences live, and the parked enhancer and adnuke scripts stay parked. Nothing new was added to reach YouTube: no autoplay flag, no allowlist, no user agent or site rewrite. Whether this changes first load playback is not measured here.

* **A History File Held Open No Longer Loses Closed Tabs**: When something else has the closed tab history open, a refused write used to be rolled back by reading the file again. That read was refused too, so closures already on disk dropped out of memory and Ctrl+Shift+T could no longer reach them, while the store also decided the file was unreadable and refused every later write for the rest of the run. The closures this process already knew are now kept as they are, so the tabs you closed before the hold and the ones you closed during it are all still reopenable. The next write after the hold is released lands on its own and saves the pending ones with it. A history this build cannot read is still refused and still left byte for byte untouched.

* **Internal Pages Render On Restore, Wake And Switch**: Restored Settings, History, Downloads, OneTab, Onboarding and release notes tabs came up as blank documents because only toolbar opened pages received their content navigation. The engine now serves every built in page when its WebView is created, so startup restore, hibernation wake and transfer rebuilds all render. A manually hibernated internal tab keeps its page url instead of waking to a blank address. Refresh on an internal page re-serves it through routing. Switching tabs never re-serves, so live page state is kept. A rejected memory tuning call on one view is traced and skipped instead of hiding the rest.

* **Drag A Tab Out To Its Own Window**: A tab can be dragged off the strip into a window of its own, and dragged back onto any open window's strip to dock. The page comes with it: the same WebView control, the same live document, its scroll position, unsaved form input, back history and running scripts. Nothing navigates and nothing reloads. Tearing off the only tab in a window moves that window instead of opening a second one. Measured against real windows with a real page; the pointer gesture that starts the drag has not yet been exercised.
* **Closing A Window Always Writes What You Need Back**: A window close now writes the closed tab history and your settings even when clearing browsing data times out or the WebView faults. Before this a failed browser cleanup jumped out of the whole write block, so a data clearing exit could finish without forgetting closed tabs or saving settings. The deadline is unchanged and a failure is still reported rather than swallowed.
* **Reordering And Edge Scrolling Restored In The Strip**: Dragging a tab slides its neighbours aside and commits the new order on release, and Escape cancels a drag without moving anything. The decisions are covered by tests: pinned tabs stay inside the pinned group and unpinned tabs outside it, a dragged tab commits within its own range, and only the outer 32 pixels of the strip scroll it. The gestures themselves have not yet been exercised with a real pointer, so this is the rule set, not an observation of the mouse.
* **Windows No Longer Share One Engine**: Each window has its own tab engine, reader state, link preview and message router. Closing one window shuts down only its own scope and leaves the settings, history, downloads and the shared WebView2 profile alone. A second open window no longer takes over the first one's tab list.
* **The Startup Snapshot Survives A Real Exit**: The last window to close writes the tabs that were actually open. Windows you closed are left out, so their tabs do not come back next launch, and the last window's own tabs are saved rather than an empty list. Repeat urls, titles and pins each keep their own row, a window left empty by a docked tab contributes nothing, and exactly one row carries the tab to reopen on.
* **Closing A Window While A Tab Is Being Dragged Into It Is Not An Error**: If the destination window closes mid drag, the transfer is abandoned and the tab stays where it was. The next drag still works. A window that fails to load is still reported as a fault rather than being treated as a decision to cancel.
* **Send All To OneTab Leaves A Page Showing**: Sending every web tab to OneTab keeps the surviving tab on screen. When the survivor was not the tab you were looking at, its WebView was collapsed or missing and the window came up blank. The tab switch that announces the survivor now does the activation too, instead of a second activation racing it and cancelling the first.
* **Floating Command Bar Removed**: The centered overlay bar is gone with its setting, onboarding choice, styles, handlers and IPC wiring. The toolbar address field is the only address UI. It shows the bare domain and reveals the full address on focus with Ctrl+L selecting all. Profiles saved while the old setting existed load normally on the standard bar.
* **Adaptive Toolbar Tint Covers Address Popup And Tab Cards**: On light site colors the address field, suggestion popup, hover states, pinned cards and close highlight now follow the tint with dark readable text. Dark site colors and tint off render exactly as before. Tint stays scoped per window.
* **Metadata Updates No Longer Reactivate Tabs**: Favicon, audio, sleep and title only updates no longer cancel an in flight tab switch or resuspend background tabs. First open, navigation and real tab switches still activate. An active address edit is never overwritten by a metadata update.
* **Session Restore Keeps Duplicates And Active Tab**: Restarting restores every saved row verbatim, including repeat urls, with pinned titles and the last active tab. Exiting with restore off empties only the startup snapshot, so Ctrl+Shift+T still reopens closed tabs. Clear data on exit also forgets closed tabs.
* **Extension Setup No Longer Blocks The UI Thread**: Unpacking, hashing, downloading and rewriting the uBlock filter files now run on a background thread, and only the WebView2 profile calls stay on the thread that owns the control. A first run used to spend over five seconds of that extraction on the UI thread. Measured on the real app: 5.2 seconds of extraction off the thread, and 90 milliseconds total on a warm start. Ordering, the retry after a failed download and the enabled state of the blocker are unchanged. WebView2 process startup is still the largest remaining startup cost and is not addressed here.
* **Closed Tab History Only Claims What Is Stored**: A closed tab whose write fails is still remembered, so Ctrl+Shift+T can reopen the tab the user closed while the history file is refusing writes. The store keeps answering that the write failed, so nothing claims the entry was saved, and a restart loses it because the file never took it. The next write that lands saves it along with the rest, in the order the tabs were closed. Ctrl+Shift+T does not consume an entry that is still on disk, so a failed removal replays on the next launch instead of opening twice. A history this build cannot parse is left byte for byte untouched and writes are refused until something can read it. Urls are stored whole, and history written by earlier versions still loads with its order, repeats and pins intact.
* **A Window Close Only Claims Writes That Landed**: The startup snapshot and settings writes a window performs on the way out now answer from the write itself. The stores catch and log write failures, so a close reported a saved snapshot and saved settings even when those files never reached the disk, which hid a locked file, a full disk or a profile the browser could not write. A failed write now shows in the close result, leaves the previous file untouched, and lets the rest of the sequence run. Settings saved from the settings page, the reader and the page message handlers keep their existing call and still never throw.
* **uBlock Origin named in Extensions**: The ad blocking switch in Settings Extensions now reads uBlock Origin and says it blocks ads and trackers. The toggle was already in Extensions and keeps the same on and off setting. It previously read as native blocking. No playback change is claimed.

# Release Note: v1.2.3

* **Centered Pinned Tab Favicons**: Pinned tabs now render as 32 DIP wide squarcles with favicons centered horizontally and vertically. Removed asymmetrical left column margins and extra empty star space on pinned cards.
* **Pinned Tab Drag And Drop Partitioning**: Pinned tabs now reorder exclusively within the pinned tab range, and unpinned tabs reorder exclusively within the unpinned tab range. Pinned drag ghosts render as compact 32 DIP squarcles with centered icons instead of wide text pills. Pinning moves the tab to the end of the pinned group, and unpinning returns it to the start of the unpinned group.
* **Standard Tab Design**: Tabs are now unified into standard cards across Stride. Removed compact icon-only mode in favor of full tab cards with site favicon, clean title, and hover close buttons.
* **Helium Tab Card Styling**: Tabs render as detached squarcle cards with 8px corner radii, 31px height, standard 190 DIP width, and equal share shrinking across the viewport. The close button now displays exclusively on hover across all tabs with a 4px rounded-rectangle highlight.
* **Helium Toolbar Alignment And Element Spacing**: Toolbar height refined to 38 DIP, with standard 28 DIP location bar height, 28x28 DIP toolbar action and navigation buttons, 6 DIP section dividers, and 3 DIP element padding matching Helium's 3 DIP base spacing system.
* **Suggestions That Start With Your History**: The address bar dropdown now blends visited pages first, then shortcuts, then web phrases. Local matches render instantly and web results append without rebuilding the list, so the flicker is gone. Turning off search suggestions now actually stops the network calls.
* **Standard Suggestion Rows**: Dropdown rows now show a per-type icon plus the page title and domain instead of one clock icon and raw URLs. Arrow keys fill the box with the highlighted row, Up from the top row and Esc restore what you typed, and Enter opens the highlighted target.
* **Suggestion Favicons And Cleaner Rows**: Rows now show the site favicon resolved from the cache, falling back to the type icon while it loads. Repeat visits sharing a page title collapse to one row. The green accent bar on the active row is gone.
* **Domain Only Address Bar**: The bar shows the bare domain instead of the full URL. Focusing it reveals the full address for editing or copying, and Enter on the untouched display reloads the page. Internal pages name themselves instead of showing blank: Search, Downloads, Settings, History, and the rest.
* **One Dropdown At A Time**: The floating command bar list now uses the same rich rows as the toolbar, and the toolbar popup stays shut while the floating panel is open. The floating bar is off by default for new profiles.
* **Type Instantly On New Tabs**: Landing on a new tab focuses the bar with everything selected. Clicking an unfocused bar selects all instead of dropping a caret, so there is no backspacing first.
* **Plus Follows The Last Tab**: The new tab button now sits right behind the last tab instead of trailing the address bar.
* **Pinned Tabs Stay Icon Only**: Pinned tabs never show a title or any close button, in compact and Full Names modes alike, and keep their narrow icon width instead of stretching with the strip.
* **Restore Lands On Your Last Tab**: Restarting with session restore now opens the tab you closed on, not the first tab. Sessions saved before this change still open on the first tab.
* **Extensions Settings Section**: Ad and tracker blocking, YouTube Enhancer and YouTube Unhook now sit together in a new Extensions section instead of being split across Privacy & Security and YouTube. Everything that changes what the browser does to a page is in one place. YouTube Enhancer and YouTube Unhook collapse so a 20-toggle group is not a wall of switches, and each one shows how many of its own settings are on while collapsed.
* **Taskbar Icon Sharpness**: Rebuilt stride.ico and stride-light.ico from the 1024 masters with the full Windows size set 16, 20, 24, 32, 40, 48, 64, 96, 128, 256 so the taskbar finds a native 24px entry at 100 percent DPI instead of scaling the nearest size. Both ICOs are now embedded as resources.
* **No Dots Truncation**: Removed ellipsis trimming across tab titles, URL label, suggestion lists, link preview, drag ghost, and context menu preview so clipped text ends clean with no dots. The URL label now uses MaxWidth 200 instead of a fixed 80 width.
* **Tab Drag Reorder**: Tabs can now be reorganised by dragging. A solid pill with the tab favicon and title follows the cursor, edge zones auto scroll overflowing strips, and the drop commits the new order. Cancelling restores the start slot.
* **Full Names Shrink To Fit**: Full Names mode now shares the strip width across every tab, capped at full card width. Opening more tabs shrinks every card so all tabs stay visible with no scrolling. Titles collapse to favicons on tiny cards, and the close button moves from the card end to the favicon overlay as cards shrink. Compact mode is unchanged.
* **Tab Strip Stays Inside The Window**: The strip no longer grows past the space it is given. Tabs shrink from full card width toward favicon width and only scroll once even favicons stop fitting. Full Names mode dropped its fixed 120 DIP floor and gives up titles for the whole strip once one title per tab stops fitting, and the default favicon mode now shrinks the same way instead of holding 32 DIP pills. Thirty tabs on a 1920 window fit end to end, against about five wide cards before.
* **Close Button Is Clickable Before It Appears**: The close slot stays live at zero opacity instead of leaving layout, so the end of every wide tab closes on click the way Helium does, with the cross fading in on hover and staying lit on the active tab. Narrow tabs still hand the job to the favicon overlay.
* **Favicon Tabs Need A Click Before The Cross**: A crowded tab that has shrunk to a bare favicon no longer offers close on hover. The cross appears only once the tab is selected, so a stray hover across a packed strip cannot close a tab you never chose.
* **Tab Titles Fade Instead Of Cutting**: Titles lose their ellipsis and soften out through a gradient mask, so a clipped title ends in a fade rather than three dots. Short titles are untouched because the mask sits past the text.
* **Tab Search Removed**: The magnifier button and its popup are gone along with the Ctrl+Shift+A binding and the controller behind them. The toolbar keeps its downloads, reader and settings actions.
* **Window Resize Floor Raised**: Minimum window size is now 760 by 480, matching the width where the toolbar already collapses its centre dock into a second row. The browser stops shrinking before the layout has to squeeze.
* **Toolbar Stops Leaving A Dead Gap**: The tab strip used to arrange itself at the width its own tabs asked for, so a 12 tab strip in a 935 DIP toolbar took 456 and left the rest empty around the plus button. The list now takes every DIP the toolbar hands over, so cards expand to fill and the plus sits at the end of the strip.
* **Address Bar Hugs Its Content**: The standard bar used to claim a fixed 38 percent of the toolbar with a 120 DIP floor, so a short or empty URL still reserved a wide hollow pill. It now starts at 90 DIP, grows to its content and caps at the old maximum, so a bare new tab page no longer carries a long empty box.
* **Reload And Address Bar Sit Tight**: The margin between the nav buttons and the address bar was 16 DIP split across three containers, which read as a large hole on a sparse toolbar. The URL domain grouping lost its left margin and the address bar its left margin, halving the gap to 8 DIP on both sides of the bar.
* **Address Bar Starts On The Left**: A new profile now puts the address bar on the left and leaves the floating command bar off. Both were the wrong way round for a first run, so every new user started with the bar on the right. Existing profiles are untouched.
* **Force Dark Mode Moved To Extensions**: The setting now sits at the top of the Extensions section instead of down in Theme, where it looked like an app appearance choice. It is not an extension underneath: it runs on Chromium's own dark engine through a browser argument, so this is about where it lives rather than how it works.
* **Enter Closes The Suggestions**: Pressing Enter shut the dropdown, but the suggestion fetch started when you typed was still running. When it landed it reopened the list over the page you had just navigated to. Closing the list now cancels that fetch, so Enter, Escape and picking a row all leave the dropdown shut.
* **Suggestion Rows Lead With The Page Name**: A visited page row already led with the page title and put the domain beside it in the dimmer second text. Search phrase rows did not. Every phrase row repeated the label DuckDuckGo Search, which took enough width to trim the phrase itself down to a few letters, so the rows all looked identical and unreadable. The phrase is now the whole row, and the list is exactly as wide as the address bar with no floor under it.
* **Inline Ghost Autocomplete Removed**: Typing used to fill the top suggestion into the box and leave the remainder selected. That ghost fought the caret, because Backspace deleted it and the next suggestion pass put it straight back, so the box looked frozen the moment the dropdown appeared. The ghost is gone from the toolbar bar, the floating command bar, and every other address entry, along with the state machine and the completion rules behind it. The dropdown stays exactly as it was. Arrow keys still fill the box with the highlighted row, Up from the top row and Esc still hand back what you typed, and Backspace or Delete on a highlighted row still gives you your query back before it edits anything.
* **Adaptive Toolbar Color**: New Layout toggle. On keeps today's behavior, tinting the toolbar with the active site theme. Off keeps the neutral toolbar on every site.
* **New Skull App Icon**: New dark and light skull mark across the window icon, taskbar, installer, and tab fallback favicon, with resized sets and a rebuilt multi resolution ICO. Dark skull shows by default and the light skull follows the light theme.
* **Rounded App Tile**: The app icon is now a rounded skull tile in every theme. stride-tile is the single 1024 master for the whole codebase. stride.ico and stride-light.ico were rebuilt from it with the full Windows size set, and every fallback PNG set was regenerated from the same art, so the taskbar, Start menu, window chrome, tab favicons, and installer all show one consistent tile. The legacy masters are deleted.

**Changes**
* **YouTube Unhook Restored**: The element-hiding features are back, covering the feed, watch page, player, and interface, with every feature in the settings list now working.
* **YouTube Hide Shorts Rewritten**: The previous version hid any item section containing a Shorts shelf, and YouTube wraps ordinary feed videos in item sections too, so real feed content disappeared along with the shelf and the page lost its scroll height. Hiding Shorts now matches YouTube's own shorts marker on the shelf and limits every structural test to a direct-child relationship, so it cannot reach content it was not aimed at. The Shorts shelf, individual Shorts in the feed grid, the left navigation entries, the channel tab and the search chip are all covered.
* **YouTube Sidebar Toggles Merged**: Hide video sidebar and Hide recommended videos are now one toggle. The old pair made no sense together. Hide recommended videos emptied the sidebar but left the column, so the video stayed narrow beside an empty black strip, and hiding the video sidebar made the first one pointless. One toggle now removes the column, and the video takes the full width. An existing Hide recommended videos setting still works and now hides the whole column.
* **YouTube Sidebar No Longer Blocks Scrolling**: The previous Hide video sidebar removed the ceiling on the player column, so the player sized itself to the full window width and reserved matching vertical space. In theater mode the player is pinned to the top of the scroller, so the description fell below the fold with no scroll range left to reach it and the wheel did nothing. The column is now hidden and YouTube's own width variable zeroed, which reclaims the space without touching the player's sizing.
* **YouTube Enhancer And Ad Skipper Parked**: The playback quality and speed preferences and the ad skipper stay switched off, so YouTube behaves exactly as YouTube intends. The scripts are parked rather than deleted, and the settings that controlled them stay in place so they can come back. Wallhaven downloads, theme colours, link preview and uBlock are unaffected.
* **Smaller Download**: Removed code that was no longer used. Dark Reader was still embedded in every build even though Force Dark Mode runs on Chromium's own dark mode flag, which accounts for most of the size. A leftover temporary extraction folder, an unused constant, several empty methods and duplicate log lines are gone.

**Bug Fixes**
* **Download Closes Browser**: Fixed the browser shutting itself when starting a download. Download landing pages call window.close once the file starts, and the WebView2 control answers that by closing the whole host window, not just the tab. Stride now detaches that built-in handler when wiring each tab, so only the tab closes and the download keeps running. The download handler also guards every native read, posts store updates without blocking, and falls back to the URL or a default file name when the native path is missing. Proven by stride.log showing WebView2's own window-close handler on the shutdown stack.
* **Taskbar Grouping And Start Icon**: Shortcuts created by the installer now carry AppUserModelID Stride to match the running process so pinned taskbar buttons group with the open window instead of opening a second button. The installer and the micro updater now notify the shell after install so the Start menu picks up the new skull icon without a manual cache clear. Stride also verifies its Start menu and taskbar shortcuts on every launch and stamps the missing AppUserModelID in place, then notifies the shell when anything changed.
